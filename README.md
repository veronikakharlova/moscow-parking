# Бесплатные парковки Москвы

Сайт, который автоматически забирает посты из вашего телеграм-канала (ссылка на карту + адрес) и показывает их на карте. Мобильной версии как отдельного приложения нет — сайт адаптивный, и его можно «добавить на экран» на телефоне как обычное приложение (PWA).

Всё ниже — бесплатные сервисы, специально подобранные так, чтобы не требовалось платить и не было точек, которые «тихо» ломаются.

## Что понадобится завести (один раз)

1. Аккаунт [GitHub](https://github.com) — там будет храниться код.
2. Аккаунт [Supabase](https://supabase.com) — база данных.
3. Аккаунт [Vercel](https://vercel.com) — хостинг сайта (можно войти через GitHub).
4. Телеграм-бот через [@BotFather](https://t.me/BotFather).

Яндекс.Карты не нужны — карта сделана на бесплатном OpenStreetMap, без ключей и регистрации.

---

## Шаг 1. Создать телеграм-бота

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram, отправьте `/newbot`.
2. Придумайте имя и username бота (username должен заканчиваться на `bot`).
3. BotFather пришлёт **токен** вида `123456789:AA...` — сохраните его, он понадобится ниже.
4. Зайдите в настройки вашего канала → **Администраторы** → добавить администратора → найдите вашего бота по username → дайте права (достаточно базовых, публиковать посты боту не нужно).

Без шага 4 Telegram не будет присылать боту посты канала — это отдельное и обязательное условие.

## Шаг 2. Создать базу данных в Supabase

1. Зарегистрируйтесь на [supabase.com](https://supabase.com), создайте новый проект (New project).
2. В панели проекта откройте **SQL Editor** → **New query**, вставьте содержимое файла [`supabase/schema.sql`](./supabase/schema.sql) из этого проекта и нажмите **Run**. Это создаст таблицу `parkings`.
3. Откройте **Project Settings → API** и скопируйте три значения — они понадобятся на шаге 4:
   - `Project URL`
   - `anon public` ключ
   - `service_role` ключ (держите в секрете, не публикуйте)

## Шаг 3. Выложить код на GitHub

В терминале, в папке проекта:

```bash
git init
git add .
git commit -m "Первая версия"
```

Затем создайте пустой репозиторий на github.com (без README, без .gitignore — они уже есть) и выполните команды, которые GitHub покажет на странице нового репозитория (`git remote add origin ...`, `git push -u origin main`).

## Шаг 4. Задеплоить на Vercel

1. На [vercel.com](https://vercel.com) → **Add New → Project** → выберите ваш репозиторий на GitHub.
2. В настройках проекта (**Settings → Environment Variables**) добавьте:

   | Имя | Значение |
   |---|---|
   | `NEXT_PUBLIC_SUPABASE_URL` | Project URL из Supabase |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon public ключ из Supabase |
   | `SUPABASE_SERVICE_ROLE_KEY` | service_role ключ из Supabase |
   | `TELEGRAM_BOT_TOKEN` | токен от BotFather |
   | `TELEGRAM_WEBHOOK_SECRET` | любая длинная случайная строка, придумайте сами |

3. Нажмите **Deploy**. После завершения Vercel даст адрес сайта вида `https://your-project.vercel.app` — это и есть готовый сайт (пока без парковок).

## Шаг 5. Подключить бота к сайту (вебхук)

Это разовая команда, которая говорит Telegram-боту, куда слать новые посты.

1. Локально в папке проекта создайте файл `.env.local` (скопируйте `.env.example` и заполните):
   ```
   TELEGRAM_BOT_TOKEN=...       # тот же токен от BotFather
   TELEGRAM_WEBHOOK_SECRET=...  # та же строка, что указали в Vercel
   SITE_URL=https://your-project.vercel.app   # адрес из шага 4
   ```
2. Установите зависимости и запустите скрипт:
   ```bash
   npm install
   npm run set-webhook
   ```
3. В ответ должно прийти `{"ok": true, ...}`.

Готово — теперь каждый новый пост в канале должен появляться на сайте в течение нескольких секунд. Проверьте, опубликовав тестовый пост со ссылкой и адресом.

## Шаг 6. Защитить бесплатную базу от «засыпания»

У Supabase на бесплатном тарифе проект приостанавливается после 7 дней без обращений к базе. В проекте уже есть файл [`​.github/workflows/keep-alive.yml`](./.github/workflows/keep-alive.yml) — он дважды в неделю сам «пингует» базу через GitHub Actions. Нужно только добавить те же ключи Supabase в секреты репозитория:

1. На GitHub откройте ваш репозиторий → **Settings → Secrets and variables → Actions → New repository secret**.
2. Добавьте `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY` (те же значения, что в Vercel).

Дальше ничего делать не нужно — GitHub Actions бесплатен для такого объёма и будет запускаться сам по расписанию.

## Локальная разработка

```bash
npm install
npm run dev
```

Откроется на `http://localhost:3000`. Для локальной проверки вебхука понадобится туннель (например [ngrok](https://ngrok.com)), это не обязательно на первом этапе.

## Как это устроено внутри

- `app/api/telegram-webhook/route.ts` — принимает пост из канала, разбирает его (`lib/parse.ts`), сохраняет в Supabase.
- `lib/parse.ts` — вытаскивает ссылку и адрес из текста поста, достаёт координаты либо прямо из ссылки на карту, либо через бесплатный геокодер Nominatim.
- `app/page.tsx` + `components/` — главная страница: карта (Leaflet/OpenStreetMap) и список.
- `supabase/schema.sql` — структура таблицы и правила доступа (сайт может только читать опубликованные записи, писать может только серверная функция).
- ИИ (Claude API) в текущей версии не используется — формат постов простой, справляются обычные правила. Если появятся посты, которые парсер не сможет разобрать, они просто не попадут на сайт (это видно в логах Vercel) — тогда можно добавить ИИ-разбор как резервный шаг.

## Что можно добавить позже

- Модерация: сейчас все посты публикуются сразу — можно добавить `is_published = false` по умолчанию и простую страницу для подтверждения.
- Fallback-разбор через Claude API для нестандартных постов.
- Фильтры по районам, обновление в реальном времени без перезагрузки страницы.
